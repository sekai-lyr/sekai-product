# 纯浏览器供音发布记录

## 用户体验

入口仍是 https://sekaisong.com/device-sharing 。第一次选择文件夹并授权，点击“开始共享”；同账号的其他设备从原歌单播放。不需要安装、Node.js、命令或复制配对码。旧客户端保留兼容，但不再是网页的使用前提。

Chrome／Edge 保存真实目录和文件句柄至本机 IndexedDB；读取时重新检查授权、大小和修改时间。凭证仅存在当前网页内存中，不持久化 token。再次开始共享时，凭已登录 Session 和 CSRF 自动更新该浏览器设备的临时凭证，保留设备 ID 及目录关联。

不支持目录句柄的浏览器使用文件夹选择框；选中的 File 仅保存在当页内存，不将媒体复制到 IndexedDB。该兼容模式关闭网页后需要重选。任何浏览器都有可能再次要求授权，不能承诺永久免确认。

共享页关闭、电脑休眠、后台冻结或断线后不能继续供音。刷新不会自动开启共享。相同浏览器同账号使用 Web Locks 防止多个共享标签页相互抢占。所有新接口沿用账号归属和 CSRF 检查。

## 验证

- 新浏览器接口测试先因路由不存在失败，随后验证未登录 401、缺 CSRF 403、跨账号 404、同一设备重新发证和旧凭证失效。
- 隔离发布构建 46 项 Java 测试通过；Node／播放器回归 15 项通过。
- 本机真实 Chrome 两个独立上下文：实际 FileSystemDirectoryHandle、IndexedDB 句柄回读、WebSocket、Range 和 WAV 实际播放；停止、刷新恢复、关闭供音页拒绝新请求均通过。目录选择器由测试返回真实的浏览器私有文件系统句柄，没有操作真实曲库。没有声称自动化测试完成了操作系统文件夹对话框的人工授权。
- 既有 23 种演出完成加载，无页面脚本异常。桌面和 390px 页面截图检查；没有逐种演出视觉基线，不声称所有动效视觉验收。
- 正式站使用一次性测试账号检查网页无需客户端、默认关闭、模块 MIME 正确及 HTTPS 浏览器 Origin 的 WSS 握手。浏览器只读检查，不在正式站自动授权真实目录。
- 正式站继续通过临时供音进程验证 2 MiB 合成文件、206 Range、未登录拒绝、停止及重连默认关闭。此项验证中转兼容性，不冒充异地实体设备的浏览器供音测试。
