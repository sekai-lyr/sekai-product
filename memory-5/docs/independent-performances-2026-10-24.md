## 共同约束

- 同一播放器、时间线和控制栏；不改登录、注册、歌单与关联流程。
- 旧模式 ID 保留，历史设置不丢失。新引擎参数独立存储，不把旧参数强行解释成新参数。
- 句子同步只依据音频时间。没有逐字时间戳不能声称逐字精确同步。
- 音频分析复用现有播放器的频谱，不创建第二个音源连接；不可用时平稳降级，不编造节拍。
- 主歌词必须完整排版，Unicode 字素不拆开；旋转/缩放后的正文也不得越过安全区。
- 字号、动态强度、画质同一交互方式；低动态偏好禁用镜头位移与持续运动。
- 暂停/拖动/切歌时一致；销毁时清理观察器、图片回调和 DOM。
- 保留仍分发的 FOLIa 源码、许可与归属。独立实现不等于可以删除已有第三方声明。

## 验收

1. 桌面 1920×1080、1366×768、1024×640，以及窄窗口 390×844；中文长句、英文长词、emoji、空歌词。
2. 逐一切换所有入口；首句前、句子切换、暂停、往前/后拖动，检查当前行。
3. 文字边界在安全区内，缺少歌词时给出可读提示，不白屏。
4. 修改设置后切歌/返回同模式仍保留；字幕字号不能造成遮挡控制栏。
5. 记录运行错误和帧耗时；不能用“加载成功”代替视觉质量与性能验收。

“超越”是设计目标，需要同歌曲、同时间、同窗口的前后对照和用户试听评价，不能由代码行数或自称原创证明。

## 本轮实际交付与边界

- 2–18 号入口接入本项目新写的 `independent-performances.mjs`；旧 ID 与历史播放入口保留。正常入口不再加载 FOLIa 演出模块，旧资源和许可仍保留。
- 17 种模式提供独立场景图形与排版变体，共用字号、动态强度、画质和模式内设置记忆。不是把上游代码改名后宣称原创。
- 19–23 号保留原有本项目实现，本轮增加排版缓存、低端设备像素比限制、短窗口安全区与控件可访问名称；本轮没有重新设计这五种模式的全部镜头。
- 唱片舞台的实时频谱改读音频分析器；无频谱数据时显示静止基线。离线演示渲染仍使用确定性示意动画，不能称为真实音频分析。
- 新引擎使用 DOM 完整文本排版及 Canvas 场景，字体加载后测量，过长文本可滚动；这不是保证任意长度文本都能在一屏内保持大字号。
- 通过 51 组模式/窗口组合检查，覆盖文本保留、前奏回跳、安全边界、水平溢出；另验证减少动态、设置恢复与销毁。
- 实际 Spring 服务的 Chrome 测试通过：共享音频播放、23 种入口加载、浏览器目录恢复。
- 尚未完成硬件分档帧耗时基准，也未完成全部模式与旧版的同歌视觉对照。“全面超越”暂不作为完成结论。

### 文字运动补充

- 单独设计词组入场/持续运动；Unicode 字素完整，超过 120 个分词的长文退回普通排版，避免大量节点逐帧更新。
- 运动根据音频时间计算，拖动后可复现；减少动态和零强度不移动词组。不把视觉交错入场称为逐字歌词同步。
- 五种既有自研演出增加与新引擎相同的均衡/高清画质选择，设置按模式保存。
- 本机无头 Chrome、17 模式 × 3 窗口、每组 40 次 `apply()` 采样，最慢一组为心象 1024×640，CPU 调用耗时 p95 约 0.7ms。该数据不包含完整浏览器呈现/GPU 合成，不代表真实设备帧率。
