# Sekai Song Player 渐进重构

## 本批已完成

- 将歌曲基本管理、歌单管理、网易云与 QQ 导入路由从 `MusicControl` 拆出，保留原有 URL、表单字段和跳转。
- 用 `MusicImportStrategy` 对接两种已有导入服务，公共策略选择放入 `MusicImportCoordinator`。
- 为登录保护、输入保留、导入结果转换、歌单归属、禁止绑定本地媒体路径增加回归测试。

## 后续优先级

1. 将 `MusicControl` 中的音频扫描、标签读取、匹配和保存拆入本地媒体服务；先为现有可达路由补回归测试，再迁移。当前控制器仍有约 1100 行。
2. 统一前端资源入口并由构建产物生成内容哈希版本，逐页替换手写的 `?v=`；先保持原静态路径可访问。
3. 对确实耗时的媒体分析提供后台任务与状态查询。上传请求完成前仍须保存并校验文件，不能直接把 `MultipartFile` 交给异步线程。
4. 使用现有日志测出热点后再加本地缓存或 Redis。Redis 需部署、失效和降级方案；目前没有足够证据证明它应先于媒体流程改造。
5. TypeScript、前端打包、CDN、播放统计和监控分独立批次引入，每批验证构建和核心页面。图片 CDN 只用于可公开缓存的静态资源，用户本地媒体不纳入。

发布前检查：运行相关单元测试、打包、核对路由清单和代码差异；涉及数据或媒体存储的变更再做线上等效流程验证。
