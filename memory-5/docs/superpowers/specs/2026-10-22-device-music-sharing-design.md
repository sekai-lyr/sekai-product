# 设备音乐共享：同账号跨设备第一版

日期：2026-10-22。状态：用户已确认方案，开发中；尚未启用。

## 目标与范围

任意正常登录用户均可绑定自己的供音电脑。首次选择目录并配对后，目录和歌曲映射持久保存；后续不依赖浏览器文件选择器恢复。供音电脑运行配套服务、网络可用且共享开启时，同一账号在其他设备登录即可听歌并使用现有歌词演出。

“关联记住”与“允许远程共享”独立：停止共享保留关联；删除设备或撤销目录才移除相应授权。电脑仅开机而未运行服务不能供音。共享默认关闭，重启服务后也不擅自开启；用户明确开启后，短暂断线允许重连恢复，手动关闭不能被重连覆盖。

第一版仅同账号，不提供公开链接、匿名访问、好友授权、音频云存储、跨账号曲库复制或开机自启动。只支持 Windows 供音电脑；播放端沿用现有受支持浏览器。用户只应共享其有权提供的内容。

## 方案选择

- 采用电脑端服务主动连接网站的加密中转：不要求公网 IP、路由器端口映射或入站防火墙规则。服务器实时转发，不写入音视频文件或缓存副本。
- 暂不采用纯浏览器供音：它仍依赖网页存活与浏览器授权，不能解决用户提出的长期关联问题。
- 暂不采用 WebRTC 直连：跨网络成功率、TURN 中转和凭证管理会扩大第一版范围。后续可作为降低服务器流量的优化。

中转不等于不传输：音频数据经过服务器和播放端，消耗供音电脑上行与服务器流量。无法阻止接收端保存已收到的内容。不承诺只要网络“正常”就无限并发；必须有明确的资源上限和离线状态。

## 组成与数据流

1. 网站“设备共享”页：列出本人设备、在线和共享状态；提供配对、开启、停止及撤销设备操作。现有登录、注册、歌单和演出布局保留。
2. Windows 配套服务：使用 Node.js 运行时，提供便携启动方式。只在本机选择目录，保存本机路径和歌曲 ID 映射；不接收远程任意路径或执行命令。关闭服务就是停止供音。
3. 服务器设备管理：MySQL 保存设备所有者、凭证摘要、撤销状态、共享开关及歌曲—设备映射，不保存本机绝对路径。启动扫描只发送映射元数据，不上传媒体。
4. 服务器实时转发：配套服务主动建立 WSS 连接，HTTP 播放请求通过已认证通道转发；传输支持有限缓冲和取消。浏览器使用同源的、受登录保护的媒体 URL。
5. 播放器适配：本机文件已可用时优先本机；否则查找本账号已共享且在线的来源，连接成功后继续使用既有播放、队列、倍速、循环、频谱和歌词演出。

目录先建立索引，按账户现有歌曲文件名和大小匹配；重名冲突不自动任选，需用户确认。新发现但不在账户曲库的文件不自动导入歌单。确认映射后按歌曲 ID 请求，重启加载保存的映射，不重新扫描整个磁盘。重新扫描由用户主动触发。

## 配对和授权

- 网站登录用户创建一次性配对凭证，5 分钟有效，只能消费一次。配套服务展示设备名称，由用户确认绑定；不能只凭用户名绑定设备。
- 配对完成后发放高熵、独立的设备凭证，服务端仅存摘要，本机保存于当前 Windows 用户受限的配置目录。不使用账号密码、网站 Session Cookie、管理员 SSH 密钥或公共测试密钥充当设备凭证。
- 每个媒体请求同时验证当前网站 Session、歌曲所属用户、设备所属用户、设备未撤销、共享开启和当前连接状态。猜中歌曲 ID 不能越权播放。
- 写操作执行 CSRF 检查；WebSocket 握手验证设备身份并限制消息类型、大小和速率。不开放任意目标 URL，避免 SSRF。
- 配套服务只按持久授权目录中的索引读取允许的音频、视频、LRC 和封面。访问前重新校验真实路径位于授权目录内，拒绝符号链接、junction、路径穿越和任意绝对路径请求。默认只读。
- 本机关联配置保存后回读核对；失败明确提示“尚未记住”，不能只因本次可播放就显示永久关联成功。

## 共享状态与停止语义

设备状态：未配对、已撤销、离线、在线但关闭共享、在线共享中。服务器每 10 秒接收心跳，连续 30 秒无心跳或连接关闭后不再分配媒体请求。

共享开启由服务器和供音服务双方确认后才显示成功。关闭先在服务器禁止新请求、取消现有传输，再通知供音服务；即使供音服务断线，服务器也必须保持关闭状态。供音端本地停止优先于服务器旧状态，重连不允许重新开启。服务器重启同样默认不恢复开启状态。

停止不能抹除已发出的数据：播放端已缓冲的片段可能继续播放，不能承诺音频在点击瞬间绝对静音。离线、源文件被删、格式不支持、共享关闭使用不同提示；不因暂时离线删除歌曲或歌单，也不自动连跳整张歌单。

## 传输和资源限制

支持 GET/HEAD、Content-Length、Content-Type、Accept-Ranges、单段 Range 的 206/416；后退和拖动进度必须取消旧请求。错误和断线不能伪装成完整的 200 响应。不把整个 FLAC/MP4读入内存，不通过 Base64 搬运完整文件。

第一版每设备同时最多 2 路媒体传输，每路在途数据最多 256 KiB，帧上限 64 KiB，使用确认和背压；超限返回明确忙碌提示。等待供音端响应最多 10 秒，连续 30 秒无媒体进展则中断。断开客户端、取消播放、停止共享和撤销设备均释放读取句柄及缓冲。

服务器关闭中转缓存和磁盘临时缓冲，返回 private/no-store；媒体 URL 不包含可长期复用的设备凭证。统计只记录字节数、状态和耗时，不记录完整本地路径、密钥或音频内容。网站显示中转流量与当前传输数；不自动购买服务或扩大套餐。

LRC 和封面通过同一权限边界读取，设置尺寸上限；保留歌曲已有的服务器歌词字段。没有歌词时照常播放但明确说明不能呈现完整同步歌词。远程视频沿用既有浏览器编码限制，不在服务器转码。

## 与既有代码的接入边界

- 增加独立设备管理、通道协议和受保护的媒体接口；不重新启用 LocalPlaybackConfig 已禁用的任意服务器文件读取接口。
- LocalLibraryService 与歌曲归属查询沿用现有用户隔离方式，设备映射采用新增表，不改写旧文件关联记录。
- local-player.js 新增远程来源分支，避免对远程 URL 调用 URL.createObjectURL 或当成本机 File 解析。普通本机模式保持原样。
- local-stage.js 与 local-video.js 继续从统一媒体元素取得音频时钟；远程流不创建重复音源节点。更换歌曲仍继承当前演出模式并从 0 秒开始。

## 验收

1. 两个独立账户配对各自设备；跨账户请求、未登录、过期配对码、重复配对码和撤销凭证均被拒绝。
2. 首次目录选择和歌曲匹配后，退出网站、关闭网页、重启供音服务，再登录无需浏览器重新选文件；共享仍需用户明确开启。
3. 另一台播放端无需本地素材，可播放、暂停、拖动、切歌并查看现有演出；本机文件播放回归通过。
4. 在读取中停止共享、杀死服务、断网、撤销设备、删除源文件，检查新请求被拒绝、连接释放、状态正确及无自动连续跳歌。
5. 路径穿越、symlink/junction 越界、伪造设备 ID、任意 URL、超大消息、慢客户端和第三路并发均被阻止。
6. 大文件拖动和并发播放时监测服务器内存及磁盘，证明没有整库上传、整文件缓冲或音频落盘。
7. 配置保存失败、同名冲突和缺失素材不能显示关联成功，不擅自改变歌单成员。

## 实施顺序与上线边界

先完成协议及鉴权测试，再做 Windows 目录索引和配置保存，然后联调流式中转，最后接网站共享页及播放器。首先在本地双账户和跨设备测试，不直接向线上用户发布未验证的远程文件服务。部署前备份程序和数据库；新表迁移须可兼容回滚。不得声称本规格已经构成功能交付。
