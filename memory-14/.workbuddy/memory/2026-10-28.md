## 启动失败排查与修复（已完成）
- 根因链：① 运行环境 Windows NIO 回环被拦截（HttpClient 构造抛 loopback connection 异常，疑防火墙/杀软/VPN/winsock 损坏）→ ② AnimeService 等三处在 Bean 构造期急切创建 HttpClient，一炸全炸 → ③ 修掉后暴露 AnimeEventService 条件装配缺失（SpringAiTools 硬依赖）→ ④ SQLite profile 被 base 的 MySQL 方言/hbm2ddl 泄漏，DDL 报 auto_increment。
- 修复：新增 `utils/SafeHttpClientFactory`（默认→IPv4 重试→null 降级），改造 AnimeService/AnimeImageRecognitionService/LocalCharacterIndexService；AnimeEventService 去掉 @ConditionalOnProperty；pom 加 `-Djava.net.preferIPv4Stack=true`；minimal/sqlite/simple 补 SQLite 方言覆盖，minimal hbm2ddl=update。
- 验证：JDK25 打包 + minimal 冒烟启动 `Started Application in 5.117s`，0 SQL 错误。注意沙箱内启动需换端口（8094 被沙箱代理占用报 55357 冲突）。
- 待办：用户侧执行 `netsh winsock reset`/检查杀软 VPN；默认 no-ai profile 需 MySQL@3306；开 AI 用 `--spring.ai.enabled=true`。
