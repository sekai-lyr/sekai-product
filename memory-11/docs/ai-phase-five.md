# 第五阶段：AI 决策质量

日期：2026-10-03。第五阶段工程实现、固定残局、模拟与浏览器回归完成。未调整卡牌数值，不宣称全卡平衡或最优AI。

## 修复和策略

- 原AI通过盖放怪兽的真实攻守判断是否攻击。新增公开信息视图：盖卡仅保留实例、盖放状态和统一风险估值，隐藏身份、攻守、效果；手牌/牌库只提供数量。效果选目标与攻击评分使用同样的边界。
- 主要阶段2实际执行决策：战斗后可盖牌、发动仍合法的资源技能或将合适的弱怪转守备。跳过战斗的回合也进入阶段2，不再直接遗漏阶段。
- 主阶段所有出牌、盖放魔法、怪兽技能均计入同一阶段行动预算；战斗最多40次调度。失败动作退出本阶段决策，避免原地重试。教学的强制攻击仍保留。
- 召唤价值扣除实际可用祭品价值，保留蓄力、多属性合奏、点燃/引爆核心；诅咒和禁止素材的怪兽不能被选。失败的祭品确认取消待选状态。
- 优先补齐点燃/引爆组合，先点燃再引爆；有可见致胜伤害时优先结算。不会为上级召唤或准备技能放弃明确的致胜攻击。
- 准备蓄力或回收技能会考虑放弃攻击的机会成本。已有蓄力的释放不会被准备逻辑误拦截。先攻、跳过战斗和阶段2不支付仅本回合有效的连击费用。
- 战斗使用规则引擎的公开预览判断已知攻守、免破与伤害；避免明知亏怪。普通及以上增加清掉最后守备怪兽后队友直接攻击的估值。高难度兼顾可见高价值目标和未知盖怪风险；致胜目标始终优先。
- 保护技能优先覆盖投入资源的核心，较高LP时保留单纯回复卡。AI盖放魔法和陷阱的日志、行动展示都不公开卡名。

难度体现在现有关卡行动预算、目标价值、未知目标风险阈值与一步后续伤害估值；没有读取隐藏信息来提高难度，也没有加入无限搜索或宣称完成通用多步博弈求解。

## 共用入口

`controller.js` 的 `chooseAiMainAction(actionCount)`、`chooseAiBattleAction()` 供浏览器与无界面模拟共同使用。选择不修改规则状态；主阶段统一由 `_executeAiPlayAction` 执行，`visuals:false`只跳过表现层。旧同步测试入口也改用共同选择器。

`strategy-balance.mjs` 不再另写召唤和技能优先级，使用共同入口、两个主要阶段及相同的结束弃牌顺序。模拟仍自动响应陷阱，不包含玩家反应时间、网络或完整动画调度，不能等同真人胜率。浏览器另行验证实际调度。

## 验证

- `npm run check`通过；497项静态目录测试、40项历史测试、50个关卡检查通过。
- 新增24项固定残局：同一入口支持双方座位、选择无副作用、技能预算、点燃引爆、补齐组合、封印与合法技能筛选、致胜攻击、蓄力准备/释放、祭品价值与合法性、阶段2、免破、攻击顺序、保留回复、保护核心与难度差异。
- 隐藏信息测试用不同攻守/效果替换同一盖卡，并用抛异常的getter阻止读取隐藏字段；攻击与效果目标选择通过。对手手牌、牌库条目同样用不可读取对象验证。
- `strategy-flow.mjs`验证真实入口、正常速度的AI回合、胜负结算、再战和返回大厅。
- `ai-decision.mjs`验证战斗→主要阶段2→盖牌→结束→下一回合，并运行至第29回合，共24次AI行动；无AI异常、无区域完整性错误、无残留锁，退出清理通过。该压力测试使用100000LP和加速等待定时器，保留生产决策、引擎及UI，不冒充自然对局的完整时长。
- 压测首轮等待超时来自脚本未处理玩家超限弃牌窗口；补齐真实点击选择弃牌后通过，无需修改正常弃牌规则。
- `motion-lifecycle.mjs`再次通过设置持久化、触屏取消攻击后技能、退出重开、后台/窗口变化及异常清理。

## 已知限制

合奏对蓄力仅34%，略低于第四阶段35%–65%的警戒区间；新策略更重视保留攻击、核心与祭品，蓄力卡组仍占优。未为美化结果修改卡牌数值或隐藏样本。后续需要继续审查合奏建立场面的成本、回收放弃攻击的价值，并结合真人对局；AI仍是有限规则评分，不擅长任意长组合或推断未知陷阱。
