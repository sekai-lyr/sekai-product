# 项目优化路线图

制定日期：2026-10-03。基于当前代码与已完成验收重新制定；此文件作为后续“第几阶段”的范围依据。

## 已完成的基础

- 第一阶段：决斗规则、取消操作、动画完成锁、战斗结算报告；详见 duel-rules-foundation.md。
- 第二阶段：三套 40 张战术试炼卡组、11 张核心卡调整与 AI 技能使用优化；详见 strategy-phase-two.md。
- 最新基线：447 项前端测试、40 项历史规则测试、50 个关卡检查通过。600 局试炼模拟均结束，不等于真人平衡完成。
- 368 张卡已有演出配置，登记了 586 段分镜；共享绘图工具。原著来源仍有待核验内容，真实融合玩法尚未建立。

## 第三阶段：决斗演出、交互与性能

状态：工程实现与自动回归已完成，详见 [第三阶段记录](duel-motion-phase-three.md)。真实手机性能及全卡人工美术验收待补测。

目标：让玩家看清谁发动、作用于谁、何时命中、如何结算，同时控制等待时间和设备负担。保留已有逐卡设计。

实施顺序：

1. 记录代表场景的基线：登场、攻击、双方破坏、魔法、陷阱响应、多人素材汇聚。测量帧耗时、长任务、峰值演出节点、清理时间与输入恢复时间。
2. 统一演出生命周期与事件顺序。逐步接入现有演出入口，使用结算前的位置及身份快照；攻击遵循起手、移动、命中、结果反馈。动画不得改变规则数据。
3. 补齐退出、重开、目标离场、后台切换、窗口尺寸变化和动画异常的取消与清理。装饰演出达到预算可降级，命中、目标和结算反馈必须保留。
4. 提供演出速度及画质档位，独立保留减少动态选项；统一粒子、镜头震动、闪光和并发预算。先测量再决定是否需要节点复用等优化。
5. 优化触屏操作：技能可通过点击菜单触达，明确选中源卡、合法目标、取消操作、不能发动的原因。状态层数、剩余次数和资源代价应在局内可见。
6. 全卡覆盖与实战验收：逐卡核对其适用演出阶段，修复错位、重复、过小、不可辨认的演出；不因已有配置就认定美术质量达标。

验收：

- 桌面、390px 手机视口及双方场地方向验证通过；攻击和素材轨迹落点可追溯到实例。
- 取消攻击后主动技、陷阱打断、目标离场、双方破坏、重开/退出等场景不产生残留节点或永久操作锁。
- 368 张卡按适用阶段遍历；代表性复杂场景实际观看，正常/减少动态模式均可理解结果。
- 在记录清楚硬件和浏览器的参考设备上，目标为桌面稳定接近 60fps、移动低画质不低于 30fps；模拟节流与真实手机数据分别报告。无法达到时明确最慢场景和限制，不虚报。
- 回归测试通过，提供前后测量结果、截图或录屏。

边界：本阶段不新增全套融合规则、不迁移服务端权威结算、不对全部卡池重做数值。祭品汇聚与融合召唤分别命名。

## 第四阶段：卡牌策略与构筑深化

状态：第一批4张支援卡、检索边界修复与构筑分析已实现，详见 [第四阶段记录](strategy-phase-four.md)。其余卡牌按批审查；真人平衡及角色能力来源核验仍待开展。

- 基于三套试炼补齐检索、回收、资源消耗与反制；先对局分析再扩展机制。
- 按小批次审查其余卡牌：角色主题、稀有度预算、触发窗口、收益、代价、反制和描述一致性。
- 区分角色能力来源、项目机制改编与尚待核验；效果唯一性不以单纯调整数值冒充。
- 卡组编辑增加低星比例、起手可行动概率和关键组合提示，明确概率不等于胜率。
- 验收：每批有清单、专项测试、双座位固定种子结果及独立测试集；超出预设胜率区间需解释或继续调整，结合真人试玩。
- 真正融合召唤如纳入此阶段，须先设计融合怪兽、素材条件、额外卡组与反制规则，再开发配套演出。

## 第五阶段：AI 决策质量

状态：已完成共用决策入口、隐藏信息边界、阶段2与策略改进，并通过固定残局、双座位模拟和浏览器回归。详见 [第五阶段记录](ai-phase-five.md)。合奏对蓄力仍偏弱，保留后续平衡工作。

- 加强召唤/祭品价值、先点燃后引爆、蓄力窗口、保留防御资源和主要阶段2的决策。
- 难度体现在策略与搜索预算，不通过读取隐藏手牌或盖卡内容获得优势。
- 复用一套无界面决策入口与实际对局执行，降低模拟器和浏览器 AI 行为偏差。
- 验收：固定残局覆盖明显致胜、避免送怪、合法祭品与组合顺序；浏览器长局无死循环，决策耗时有上限，隐藏信息边界有测试。

## 第六阶段：联机一致性与恢复

- 首先审计现有房间、动作校验、共享随机数、回合确认与快照机制，复用已经有效的实现。
- 定义对局 ID、回合号、动作序号和幂等规则，测试重复、乱序、延迟与重连。
- 明确权威规则运行位置及隐藏信息边界，再推进服务端权威结算；不得把客户端上传的最终状态当作可信裁决。
- 断线恢复包含可见状态、待响应窗口与操作权限；胜负和奖励幂等。
- 验收：两个独立浏览器实际对战；弱网、断网恢复、重复包、并发结算与非法动作测试通过。账号/收藏/奖励相关变更运行服务端测试。
